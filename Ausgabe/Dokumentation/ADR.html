ADR-001 – Ein Thema wird genau einmal erklärt

Entscheidung

Fachliche Inhalte werden nur einmal gepflegt. Alle Unterrichtsmaterialien verweisen auf diese Quelle.

ADR-002 – Standards vor Implementierungen

Entscheidung

Standards (z.B. SQL) werden getrennt von Implementierungen (z.B. SQLite, Oracle, PostgreSQL) dokumentiert.

ADR-003 – Publishing-Profile

Arbeitsheft

Zusammenfassung mit Seitenumbrüchen.

Referenz

Lehrerband, Material, Lösungen und Quellen werden zusammengefasst und ohne erzwungene Kapitelumbrüche erzeugt.

Präsentationen

Eigenes Profil.

Lernkontrollen

Keine Zusammenfassung. Jede Lernkontrolle und jede Lösung ist ein eigenes Dokument.

ADR-004 – Einheitliche Werkteilstruktur

01_Arbeitsheft 02_Lehrerband 03_Material 04_Loesungen 05_Praesentationen 06_Dateien 07_Quellen 08_Bilder 09_Lernkontrollen

Technische Dateien liegen in Unterordnern (z.B. json).

ADR-005 – Build und Publishing

Quellen liegen auf main. Generierte Dokumente werden über GitHub Pages veröffentlicht. Ausgabeformate: HTML, DOCX und PDF.

ADR-006 – Single Source of Truth

Status

Akzeptiert

Entscheidung

Markdown ist die einzige Quelle (Single Source of Truth).

Alle anderen Formate werden automatisch erzeugt: - DOCX - PDF - HTML - später ggf. EPUB

Konsequenzen

  • Keine manuelle Bearbeitung generierter Dokumente.
  • Änderungen erfolgen ausschließlich an Markdown-Dateien.

ADR-007 – Build-Artefakte

Status

Akzeptiert

Quellen liegen auf main.

Generierte Artefakte werden ausschließlich durch die Build-Pipeline erzeugt und über GitHub Pages veröffentlicht.

Sie werden nicht versioniert.

ADR-008 – Dokumenttypen

Arbeitsheft

Arbeitsdokument mit Seitenumbrüchen pro Kapitel.

Referenz

Lehrerband, Material, Lösungen und Quellen. Fortlaufendes Layout ohne erzwungene Kapitelumbrüche.

Präsentation

Eigenes Präsentationslayout.

Lernkontrollen

Jede Lernkontrolle und jede Lösung wird als eigenes Dokument veröffentlicht.

ADR-009 – Nummerierung

Status

Akzeptiert

Ordner und Werkteile werden dauerhaft zweistellig nummeriert.

Beispiele: 01_Arbeitsheft 02_Lehrerband 03_Material

Die Nummern sind Bestandteil der Projektstruktur und werden nicht verändert.

ADR-010 – Wiederverwendung

Status

Akzeptiert

Fachliche Inhalte werden nicht mehrfach gepflegt.

Klassenmaterialien verweisen auf Grundlagen und Werkzeuge.

ADR-011 – Durchgängige Beispiele

Status

Akzeptiert

Grundlagen verwenden nach Möglichkeit eine gemeinsame Beispieldomäne.

Beispiel SQL: - Schüler - Lehrkräfte - Klassen - Fächer - Räume - Noten

Dies erleichtert das Verständnis über mehrere Kapitel hinweg.

ADR-012 – Progressive Offenlegung

Status

Akzeptiert

Inhalte werden schrittweise aufgebaut.

Klasse 7 → Grundlagen Klasse 8 → Vertiefung Klasse 9 → Anwendung Klasse 10 → Erweiterung

Fortgeschrittene Themen folgen später.

ADR-013 – Technologieunabhängigkeit

Status

Akzeptiert

Das Lehrwerk vermittelt zuerst Standards und Konzepte.

Beispiele: - SQL statt SQLite - Git statt GitHub

Produktspezifische Informationen gehören in den Bereich Werkzeuge.

ADR-014 – Vom Allgemeinen zum Konkreten

Status

Akzeptiert

Didaktische Reihenfolge:

  1. Konzept verstehen
  2. Allgemeine Regeln
  3. Werkzeug anwenden
  4. Im Unterricht einsetzen
  5. Vertiefen

Dieses Prinzip gilt projektweit.
